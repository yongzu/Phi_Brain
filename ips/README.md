# IPS · Phi Brain — Discover · Define · Develop · Deliver

Iterative Problem Solving(문제해결 월드컵 3라운드) 과제 정리. 더블 다이아몬드 네 단계를 한 페이지에 이어 담는다.

- 페이지: https://yongzu.github.io/Phi_Brain/ips/
- 로컬: `node tools/dev-server.js . 5510` → http://localhost:5510/ips/index.html (`?static` 등장 애니메이션 끔, `#paper-01`~`#paper-05` 논문 패널 바로 열기)
- 파일: `index.html`(본문) · `ips.css`(스타일, yongzu/BI에서 가져옴) · `ips.js`(논문·인터뷰 데이터와 인터랙션) · `cursor-*.svg`(Phi Brain 커서) · `img/phi-*.webp`(Deliver 화면 캡처 — 본인 계정 실제 데이터, 다시 찍는 법은 HANDOFF 2절) · `process-map.svg`(문제→해결 도식, `node tools/process-map.js`)

## 페이지 구성

히어로 → **Discover** 01 핵심 문제 → 02 서비스 블루프린트 → 03 정량 조사 → 04 정성 조사 → 05 제출 데이터 → 06 Discover 결론 → **Define**(단계 표지) 07 5 Whys → 08 인사이트·HMW → 09 성공 기준 → **Develop** 10 해법 후보 → 11 평가·선택 → **Deliver** 12 최종 해법 → 13 부차 해법 → 14 검증 계획·한계 → 15 버전 로그.
진행 방식(더블 다이아몬드)은 섹션이 아니라, 히어로 제목에 마우스를 올리거나 누르면 뜨는 팝업이다.
헤더의 Discover·Define·Develop·Deliver는 각 단계로 이동하고, 읽고 있는 단계가 표시된다. 좌측 목차도 단계별로 묶었다.
01~15 섹션(06·16 제외) 맨 아래에는 그 섹션을 한 줄로 요약한 **검은 인사이트 박스**가 있다.
페이지 전체가 **문제 1**(가장 중요)로 수렴하도록 짰다. 각 섹션 첫 문장이 어느 문제를 증명하는지 밝힌다 — 03 = 문제 1, 04 = 문제 1·2·3, 05 = 문제 2·3.

## 히어로

> **Phi에서 배운 인사이트를 자신의 디자인에 적용하고 있나요?**
> 저널링의 효과는 두 가지다. Findings(배우거나 깨달은 내용)는 나의 디자인에 적용되고, Future Item(해야 할 일)은 구체적인 행동으로 수행된다.
> 그러나 Phi 학습자는 저널을 다시 보지 않아, 학습 성찰이 일어나지 않는다. Phi에 다니는 가장 중요한 이유인 배우고 성장하기가 실제로 이뤄지지 못한다.

## 01 핵심 문제

직접 겪은 불편과 동료 인터뷰(6명)로 정의했다. 문제 1은 크게(전체 폭 · 큰 번호·제목 · 하단에 "Phi에 다니는 가장 중요한 이유인 배우고 성장하기가 실제로 이뤄지지 못한다"), 그 아래 "문제 1과 함께 나타나는 부차 문제" 라벨과 함께 2·3을 테두리만 있는 작은 박스로 둔다.

### 문제 1 (가장 중요 · Findings). 저널을 다시 보지 않아 학습 성찰이 일어나지 않는다
- **1-1 Findings를 다시 보지 않는다** — 다시 읽지 않아, 깨달은 내용이 체화되지 않고 디자인에 적용되지 못한다. (옛 B1)
- **1-2 기록의 중심이 외부 앱이다** — 수업 맥락과 정리 체계는 외부 앱에 있고, 저널은 이를 옮겨 쓰는 사본이 된다. (옛 A1+A2)
- **1-3 과목별로 찾을 수 없다** — 디스코드 저널은 날짜순 수직 구조라 과목별로 모아 다시 보기 어렵다. (옛 A3)

### 문제 2 (Future Item · 셀프 피드백). 해야 할 행동과 과제를 수행하지 않는다
- **2-1 Future Item은 완료가 추적되지 않는다** — 저널에 매일 누적해 다시 쓰거나 외부 일정 앱으로 옮기고, 완료 여부는 남지 않는다. (옛 B2)
- **2-2 셀프 피드백을 미루다 놓친다** — 세션 직후 쓰지 못하면 다음 날로 밀리고, 링크를 다시 찾는 과정에서 잊힌다. (정성 조사 질문 05)

### 문제 3 (Phi LMS). LMS로 과제 현황과 우선순위를 알 수 없다
LMS = 교육과 학습 과정을 통합 운영·관리하는 시스템.
- **3-1 제출 현황 파악이 어렵다** · **3-2 우선순위를 정하기 어렵다** · **3-3 필요한 링크가 흩어져 있다** (옛 C1~C3)

> 인사이트 — 저널은 쓰는 데서 끝나고, 다시 보고 적용하고 수행하는 단계로 이어지지 않는다.

## 02 서비스 블루프린트

6단계(세션·노트 → 저널 작성 → 할 일 관리 → 과제·셀프 피드백 제출 → 제출 확인 → 다시 보기) × 학습자 행동 / 접점·지원 시스템 / 백스테이지. 문제 배지(1-1 ~ 3-3)가 있는 칸에 마우스를 올리거나 누르면 해당 문제가 팝업으로 보인다.

> 인사이트 — 문제 1은 6단계 다시 보기에서 드러나지만, 시작은 1·2단계에서 기록이 흩어지는 데 있다.

## 03 정량 조사 (논문 5편) — 문제 1의 근거

**A. 기록은 다시 볼 때 배움이 된다** (문제 1이 왜 중요한가)
1. 조성범·한송이 (2023) 대학생의 e-포트폴리오 제작 경험 — 정리하지 않으면 깨달음은 흐려진다.
2. 강인애·유승현·강연경 (2011) 학습성찰도구로서 e-포트폴리오 활성화 — 성찰저널 240편 분석에서 학습조절능력 향상 54.17%, 학습과정 강화 27.08%. 설문에서는 51.21%가 쉬운 편집·관리를 요구했다.

**B. 그런데 쌓일수록 다시 보기 어렵다** (문제 1이 왜 생기는가)
3. Bruce·Jones·Dumais (2004) Information behaviour that keeps found things found — 보관 방법 평균 4.87가지, 안 보이면 잊는다.
4. 이수연·이용정 (2020) 대학생 개인정보관리 행태 요인 — 41.7%가 저장 위치를 기억해서 찾는다.
5. 지윤재·이혜은 (2022) 대학생 파일관리 행태 — 학생은 날짜가 아니라 과목으로 정리한다(파일명 날짜 표기 20% 미만).

> 인사이트 — 성찰은 기록을 다시 볼 때 일어나지만, 날짜순으로 쌓인 기록은 다시 찾기 어렵다.

## 04 정성 조사 (동료 학습자 6명) — 문제 1·2·3의 근거

질문 6개와 정리한 답변이 박스로 들어가 있다(3개씩 2줄, 옛 질문 2·3은 하나로 합침). 각 박스에서 핵심 문장 한 줄은 굵게 표시. 박스 라벨에 관련 문제 번호가 붙는다(질문 01~03 → 문제 1, 04·05 → 문제 2, 06 → 문제 3, `INTERVIEW_QA`의 `problem`).

1. 매일 쓰려 하지만 미루거나 건너뛴다(작성 10~30분, 이유는 내용 고민·공개 부담·세션 직후 시간 부족).
2. 매일 다시 보는 응답자는 없었다(주 1회 안팎). 날짜별 수직 구조와 하이라이트 부재로 특정 내용을 찾아보기 어렵다.
3. Findings와 수업 기록은 노션·옵시디언·피그마·맥북 메모에 정리한다.
4. Future Item은 다이어리·메모 앱·문서·일정 관리 도구에서 따로 관리한다.
5. 과제는 잘 놓치지 않지만 셀프 피드백은 반복해서 놓친다(다음 날로 밀리면 접근 링크를 다시 찾는 게 불편해 잊는다).
6. 해야 할 과제는 LMS·캘린더·문서에서 보고, 제출 여부는 기억에 의존하다 결국 스프레드시트로 확인한다.

**종합** — 저널은 다시 보는 기록이 아니었다. 매일 다시 보는 응답자는 없었다.

> 인사이트 — 저널은 주 1회 훑는 기록으로 남고, 할 일과 셀프 피드백은 각자의 기억에 맡겨진다.

## 05 제출 데이터 (수료조건 확인 대시보드 · 28명 · 0~3주차) — 문제 2·3의 근거

과제는 비교 기준, 셀프 피드백은 문제 2(해야 할 과제를 수행하지 않는다)의 근거다.

**과제 — 마감이 지난 509건**

| 분반 | 건수 | 제때 제출 | 지각 | 미제출 |
|---|---|---|---|---|
| A반 13명 | 221 | 216 (97.7%) | 3 (1.4%) | 2 (0.9%) |
| B반 15명 | 288 | 262 (91.0%) | 19 (6.6%) | 7 (2.4%) |
| 합계 | 509 | **478 (93.9%)** | 22 (4.3%) | 9 (1.8%) |

지각·미제출을 한 번이라도 한 사람 13명/28명.

**셀프 피드백 — 대상 728칸**

| 주차 | 제출 | 미제출 | 분모 | 제출률 |
|---|---|---|---|---|
| 0주차 | 241 | 39 | 280 | 86.1% |
| 1주차 | 120 | 90 (160−70) | 210 | 57.1% |
| 2주차 | 40 | 170 (240−70) | 210 | 19.0% |
| 3주차 | 7 | 21 | 28 | 25.0% |
| 합계 | 408 | 320 | 728 | **56.0%** |

0주차를 빼면 37.3%(444칸 중 167칸). 1인 평균 제출 14.6개.

**집계 기준** — 과제는 마감 전 빈칸을 빼고 o·지각·x만 셌다. 셀프 피드백은 시트의 o·x를 그대로 세되, A·B 분반의 수강 과목 차이와 수업이 열리지 않은 과목(SI 세션 없음)을 반영해 1·2주차 미제출에서 각각 70칸을 뺐다.

> 인사이트 — 과제는 93.9%를 제때 내지만 셀프 피드백은 56.0%만 낸다. 현황이 한눈에 보이지 않으면 밀리는 일부터 수행되지 않는다.

## 06 Discover 결론

Discover에서 확인한 핵심은 문제 1이다. 저널링의 가장 중요한 효과인 학습 성찰이 일어나지 않는다.

> 저널은 쓰이지만 다시 읽히지 않아, 배운 것이 나의 디자인으로 이어지지 않는다.

문제 1의 근거를 세 칸으로 묶는다 — **왜 중요한가**(논문 01·02: 기록은 다시 볼 때 배움이 된다, 성찰저널 240편에서 학습조절능력 향상 54.17%·학습과정 강화 27.08% — 히어로에서 옮겨 옴) · **실제로 일어나는가**(정성 조사: 매일 다시 보는 응답자는 없었다) · **왜 생기는가**(원인 단서: 1-2 외부 앱 중심 · 1-3 과목별로 찾을 수 없음, 논문 03~05 · 작성 부담, 질문 01).

해법처럼 읽히는 표현(옛 결론 "과목별로 모아 다시 보여주는 구조가 없다", Develop 메모)은 Discover에서 뺐다.

## Define (07~09)

**07 5 Whys** — 출발: 문제 1. 각 단계에 Discover 근거를 붙였다.
1. 왜 다시 보지 않나 → 다시 봐도 원하는 내용을 찾을 수 없다 (질문 02 · 논문 03)
2. 왜 못 찾나 → 날짜순으로만 쌓이고 과목·중요도로 모이지 않는다 (1-3 · 블루프린트 2단계 · 논문 05)
3. 왜 안 모이나 → 정리는 외부 앱에서, 저널은 옮겨 쓰는 사본 (1-2 · 질문 03)
4. 왜 사본이 되나 → 쓴 뒤 다시 돌아올 이유가 없다, 다시 보는 쪽은 개인 노트 (블루프린트 6단계 · 논문 03)
5. 왜 돌아올 이유가 없나 → 저널링이 '쓰기'까지만 짜여 있고 다시 꺼내 보는 단계가 없다 (블루프린트 6단계 백스테이지 · 논문 01, **추론**으로 표시)

> 근본 원인 — 저널링은 쓰는 데서 끝나도록 짜여 있어, 배운 것을 다시 꺼내 보는 단계가 없다.

**08 인사이트 · HMW** — POV: Phi 학습자는 배운 것을 과목별로 다시 꺼내 보는 자리가 필요하다. 저널이 날짜순 사본으로 쌓여, 쓰고 나면 돌아올 이유도 방법도 없기 때문이다.
핵심 HMW(문제 1): 어떻게 하면 저널에 쓴 Findings를 다시 꺼내 보고, 자신의 디자인에 적용하게 할 수 있을까? 부차 HMW: 문제 2(Future Item을 완료까지) · 문제 3(현황·우선순위를 한눈에).

**09 성공 기준** — 목표값 없이 Discover 기준값과 확인 방법만: 다시 보는 빈도(주 1회 남짓) · 원하는 내용을 찾는가(어려웠다) · Findings 적용 사례(측정 안 함) · Future Item 완료(측정 안 함) · 셀프 피드백 제출률(56.0%).

## Develop (10~11)

**10 해법 후보** — A 수업 루틴(A1 주간 회고 · A2 세션 시작 공유) · B 디스코드(B1 과목 태그 규칙 · B2 리마인드 봇) · C 기존 앱(C1 템플릿 · C2 자동 옮기기) · D Phi Brain(D1 쓰는 곳에서 과목별로 모임 · D2 중요한 문장만 모아 보기). A~C는 비교용 후보로 실행하지 않았다(페이지에 명시).

**11 평가 · 선택** — 기준: 찾을 수 있게 되는가(Why 1·2) · 이중 작성이 사라지는가(Why 3) · 다시 돌아올 이유가 생기는가(Why 4·5). 선택 D(Phi Brain), A는 남은 한계(Why 4·5)를 보완하는 방법으로 남김.

**15 버전 로그**(Deliver 맨 끝으로 옮김) — docs/STATUS.md · git에서 실제 이력만: 9/11 MVP 되돌림 → 9/14 빈 과목 숨김 → 9/16 Finding 하나가 박스 하나 · 별표 박스 단위 → 9/17 즐겨찾기 필터 → 9/22 하이라이터 3색 · 번호마다 박스 · 드래그만으로 서식.

## Deliver (12~15)

**12 최종 해법** — ① 쓴다·표시한다(Journaling) → ② 모인다(Findings) → ③ 다시 본다(Archive 과목 필터) + ④ 적용은 학습자의 몫(Future Item 등록으로 행동 추적). 캡처는 본인 계정의 실제 저널(Journaling은 9/16).

**13 부차 해법** — Future Item(문제 2, 본인 계정 실제 캡처) · Assignment Manage(문제 3, 배포 사이트 읽기 전용 표 2주차 캡처).

**14 검증 계획 · 한계** — 사용자 테스트는 아직 하지 않았다. 같은 동료에게 같은 질문(정성 조사 02·03) + 적용 사례를 새로 묻고, 09 기준값과 비교한다. 한계: 다시 보러 오라는 알림 없음 · 로그인 전에는 이 브라우저에만 저장.
