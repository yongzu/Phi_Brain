# IPS 모션 요약 영상 (Remotion)

IPS 페이지(`ips/`)의 핵심만 담은 약 2분 12초 모션 영상(로고 인트로 두 번 포함). 1920×1080 · 60fps · 무음(소리는 편집에서 추가 예정).
배포 폴더(`design/` + `ips/`)에 들어가지 않는다.

```bash
cd video/ips-motion
npm install          # 처음 한 번
npm run pull         # 실제 Phi Brain 데이터 · 앱 CSS → data/ (git 제외, 9~12번에 필요)
npm run studio       # 브라우저 미리보기 + 타임라인
npm run render       # out/ips-motion.mp4
```

- 장면 파일: `src/scenes/S01Question.tsx` … 한 장면 = 한 파일, 길이는 각 파일의 `*_DURATION`(초 단위 `sec()`).
- 순서: `src/Video.tsx`의 `SCENES`. `enter`('left' 오른쪽에서 / 'up' 아래에서)가 있는 장면은 앞 장면을 밀어내며 슬라이드로 들어온다(0.9초 겹침, `cubic-bezier(0.76, 0, 0.24, 1)`) — 이때 앞 장면은 흐려지는 퇴장을 하지 않는다(`SceneExit`). 없으면 페이드 아웃 → 페이드 인.
- 디자인 규칙: `src/theme.ts` — 페이지와 같은 잉크 #333 + 흰색, 투명도 100·70·20%, 곡선 `cubic-bezier(0.22, 1, 0.36, 1)`. 7·8번 D 화면은 검정 `black`(#000000 — 뒤의 로고 인트로 바탕과 같게, 사용자 지시), 그 위에서는 같은 위계를 흰색에(`onInk2` 70% · `onInk3` 20% — 로고 인트로 어두운 구간과 같은 값).
- 공통 모션: `src/motion.tsx` — `Reveal`(흐림 → 선명 + 위로), `Scene`(끝 0.4초 흐려지며 퇴장), `Tag`(작은 라벨 — 기본 `text` = 박스 없는 회색 70% 굵은 글씨, `soft` = 흰 박스 + 테두리). 잉크 박스 + 흰 글씨 라벨은 쓰지 않는다(2026-09-27 사용자 지시), `Typewriter`(한글 타이핑 — 초성 → 초성+중성 → 받침 순서로 찍고 커서가 따라감, 남은 글자는 투명하게 자리를 잡아 가운데 정렬도 흔들리지 않음).
- 글꼴: Pretendard(SIL OFL, `public/fonts/`).

## 로고 인트로 (약 7.75초)

로고 타이포 모션. 단독 컴포지션 `LogoIntro` → `npm run render:intro` → `out/logo-intro.mp4`. 본편 `IpsMotion`에도 같은 것이 두 번 들어 있다 — 맨 앞, 그리고 8번 선택 뒤(로고 화면 자리).

- 베지어 구간(확대 컷 + 자간 좁히기)은 검정 바탕(#000000) · 흰 윤곽선 · 흰 70% 핸들/조절점 · 흰 20% 가이드 — 영상 전체의 투명도 위계(100·70·20%)를 흰색에 그대로. 워드마크가 오른쪽으로 가기 시작하면서 0.6초 동안 흰 바탕 · 잉크 글자로 서서히 반전.
- 0:00–0:02.85 글자 확대 P → B → n(0.95초씩 하드 컷): 원형으로 읽히는 모양에서 시작해 베지어가 제자리로 온다 — P 굵기(실제 Medium → Bold 보간), B는 Figma에서 볼의 점만 골라 옮기듯 세로 획은 그대로, 아래 볼(140)이 먼저 늘어나기 시작하고 위 볼(80)이 0.25초 뒤 따라붙어 둘이 1.05초에 같이 끝난다(가운데 이음 점은 둘의 중간), n 획 굵기 + 어깨 높이. 가장 많이 움직이는 점을 지나는 가이드가 따라간다. 컷마다 카메라가 상하좌우로 움직인다(줌은 그대로) — P 위 → 아래, B 왼쪽 → 오른쪽, n 아래 → 위(`SHOTS[].pan`).
- 0:02.85–0:04.35 워드마크: 카메라가 글자 면에 붙은 데서(화면 가운데는 두 줄 사이 빈 곳이라 완전한 검정) 뒤로 빠지며 글자가 드러난다 — 사용자가 준 After Effects 카메라(Z 0 → -1081.7)를 미리보기에서 재어 맞춘 1.55초 · 거리 진행도 `cubic-bezier(0.35, 0, 0, 1)`, 화면 배율 = 1 / 진행도. 글자는 처음부터 원래 자간(-40). 가이드(확대해도 1.5px)는 글자가 드러날 때 나타났다가 1.4초 안에 사라진다. 끝 크기는 줌이 없던 때와 같다.
- 0:04.35–0:07.75 워드마크가 크기 그대로 1.6초에 걸쳐 오른쪽으로 가고, 왼쪽에 로고 마크 칸이 가운데부터 채워지며 마크 전체가 불투명도 0 → 100%(0.6초)로 나와 헤더와 같은 조합(마크 = 워드마크 잉크 높이, 간격 0.24배)으로 선다. 마크는 한 경로로 그려 칸 사이 가는 선이 없다. 끝 0.5초 흰색으로 빠짐.
- B와 a는 점이 많아 보여 추출할 때 매끄럽게 이어진 곡선을 합쳤다(오차 4단위 이하, B 22 → 16점, a 30 → 17점).
- 글자 윤곽선은 `src/intro/logo-glyphs.json`(Helvetica Neue Bold에서 추출, 자간 -40 · 줄 간격 809는 첨부 워드마크에서 잰 값). 다시 뽑기: `node tools/extract-logo-glyphs.mjs [폰트 경로]` — 폰트 파일은 저장소에 넣지 않는다.

## 사용 장면(9~12) — 실제 앱 화면 · 실제 데이터

- **실제 데이터**: `npm run pull` → `tools/pull-real-data.mjs`가 D1 원격 DB `phi-brain`을 읽기 전용으로 조회해 `data/real.json`에 저장(저널 · Findings 별표/숨김 · Future Item 보드 · 3주차 제출 대상 · 과제 공지 · Gmail 연결 주소 · 닉네임, Gmail 토큰 열은 읽지 않음). wrangler가 사용자 Cloudflare 계정으로 로그인돼 있어야 한다. `data/`는 git 제외 — 실제 저널은 Git에 넣지 않는다(AGENTS.md). 이 파일이 없으면 본편을 렌더할 수 없다.
- **앱의 실제 CSS**: `tools/sync-app.mjs`가 `design/style-kit/theme.css` + `design/prototypes/phi-brain.css`를 그림자 DOM용으로 옮겨 `data/app.json`에 저장(`:root` → `:host`, `html` · `body` → `.phi-app`, `100vw/vh` → 앱 창 크기, 이미지 → data URI, `:hover`는 `[data-hover]` 짝 추가, 전환 · 애니메이션은 끔). 앱 CSS가 바뀌면 `npm run pull`만 다시.
- **그리는 방법**: `src/app/AppScreen.tsx` — 앱 마크업을 1440×810 "앱 창"에 그리고 화면(1920×1080)에 꽉 차게(4/3배) 담는다. 확대는 쓰지 않는다(`WHOLE` — 사용자 지시, 커서가 늘 화면 안). 보여야 할 곳은 페이지 스크롤로 맞춘다(카메라 기능은 AppScreen에 남아 있음). 커서는 앱의 실제 커서 그림(`design/prototypes/cursor-arrow · pointer · text.svg`)을 앱 크기 그대로, 버튼 위에서는 앱의 호버 모양. 순서가 바뀌는 것(Findings 별표, Future 박스 별표)은 같은 키끼리 전 자리 → 새 자리로 옮기고(FLIP), 완료한 항목은 접히며 사라진다.
- **마크업**: 앱 템플릿을 옮겨 왔다 — `src/app/shell.ts`(머리줄 · 탐색 · 저널 작성칸 · 토스트, home.html), `findings.ts`(journal.js의 Finding 자르기 · 정렬 · 박스), `future.ts`(future.js의 주차 · 박스 · 항목), `assignment.ts`(assignment.js의 표 · 과제 내용 팝업, 공지 정리는 `design/prototypes/assignment-notice.js`를 그대로 import). 영상 속 "오늘"은 2026-09-27 15:00으로 고정.
- **영상에서만 바꾼 것**: 왼쪽 탐색은 Course Agent 묶음(과목 12개)을 빼고 머리줄 아래에 고정(스크롤해도 제자리, 내비게이션 바처럼 — 사용자 지시), 개발용 안내 문구(prototype-note) 뺌, 9번 알림 문구 "Findings 3개 · Future Item 1개 추가했어요"(앱은 "N개 Future Item 등록됨"), 12번 IPS 제출 확인 칸의 파란 강조(바뀐 칸 표시), Future 보드의 IPS · BI 즐겨찾기는 영상 시작 때 해제 상태로 두고 별표를 누른다(실제 데이터는 이미 둘 다 즐겨찾기). 12번 "제출 확인"은 새로고침으로 바뀌는 모습을 보여 주는 연출 — 실제 IPS 3주차는 아직 미확인이다.
- 9번에서 입력하는 Finding 세 줄은 사용자가 준 문장, Future Item은 이 Finding에서 나온 실제 BI Future Item.
