# Phi Brain — 디자인 방향

## 최신 UI 수정 (2026-09-12, 사용자 요청 · Codex)

- 과목 정식 약어는 EWA. 기존 EAI는 호환 별칭으로만 처리하며 기존 항목·즐겨찾기·저널 과목 선택을 EWA로 읽는다.
- Journaling 다룬 과목에 General 추가. General 하나를 선택한 저널의 Future Item은 General로 등록한다.
- 다룬 과목 선택칸의 음수 왼쪽 여백을 제거해 AL 선택 배경이 잘리지 않도록 수정.
- Future Item에 등록하기는 정리하기 왼쪽의 기본 미체크 옵션이다. 체크 후 정리하기를 누르면 Future Item 등록을 수행한다. 등록 성공 후 체크 해제; 실패 시 유지하고 재시도 가능. AI 정리는 여전히 미연결이다.
- 저널 체크리스트 원은 9px, Future Items 완료 원은 10px로 축소.
- 이후 본문의 예전 EWA→EAI 및 등록 버튼 위치 설명보다 이 절을 우선한다.

현재 기준: `92d1808`의 Journaling·Future Items 프런트엔드 프로토타입. 아래 초기 제안보다 이후 확정 스타일과 화면별 구현 절을 우선한다. Assignment Manage 본문은 미구현이다.

## 적용 제안

글과 여백을 중심으로 하고, 필요한 순간에 내용을 펼친다.
사용자의 자기소개 사이트와 연결되는 분위기 속에서 긴 저널을 읽고 쓰기 편한 밀도를 목표로 한다.

| 타이포그래피 | 산세리프, 본문 약 16px, 넉넉한 행간. 한글 가독성 우선 |

## 화면별 제안

- 저널 목록: 날짜, 제목, 과목명. 선택하면 기록 열기.
- 작성: 날짜와 큰 글쓰기 영역, 적은 도구.
- 검토: 정리 항목 중심, 원문 근거 필요 시 펼치기, 데스크톱 비교 모드.
- 과목: 텍스트 과목 목록과 4F별 기록 탐색.
- 실행: 작은 체크 표시, 실행 문장, 보조 과목명.

## 인터랙션 제안

- 펼침·접힘은 약 200ms의 자연스러운 전환.
- hover와 키보드 focus에 은은하지만 인지 가능한 반응.
- 저장 후 작은 저장됨 표시.
- AI 처리 중 원문을 유지하고 정리 중 상태 표시.
- 터치와 키보드로도 기능을 찾을 수 있게 한다. hover만으로 필수 기능을 노출하지 않는다.
- 본문과 상태 정보의 대비를 확보하고, 움직임 줄이기 설정을 고려한다.

## 확정된 스타일 키트 (2026-09-11, 사용자 제공 · Claude Code 반영)

사용자가 `yongzu.github.io`에서 실제로 추출한 스타일 키트(CSS 토큰 + 인터랙션 JS)를 그대로 제공했다.
더 이상 레퍼런스를 보고 짐작하는 단계가 아니라, 이 토큰이 실제 소스다.

- 위치: `design/style-kit/`(`theme.css`, `interactions.js`, `README.md`, `example.html` — 원본 그대로 보존, 재스킨은
  `:root` 토큰만 덮어써서 하고 컴포넌트 규칙은 건드리지 않는다).
- 색상·타이포·이징 등 정확한 값은 `theme.css` §1의 CSS 커스텀 프로퍼티가 유일한 출처다. 이 문서에 수치를 중복 기록하지 않는다.
- 확정된 특징: 폰트 Pretendard, 라이트 전용(`color-scheme:light` 고정 — 다크 모드 없음), 뚜렷한 accent 색 없이 회색조
  중심(과목별 12색 사용 안 함 방향과 일치), 채워진 버튼은 쓰지 않고 전부 고스트/텍스트 버튼, hover-reveal 리스트·아코디언·
  드로어·검색 드롭다운의 인터랙션 타이밍까지 코드로 확정됨(각각 180–520ms, `cubic-bezier` 이징 지정, `prefers-reduced-motion` 대응 포함).
- Claude Code가 이 키트를 적용해 홈 화면 초안을 만들었다: `design/prototypes/home.html`
  (+ 추가 컴포넌트 전용 `design/prototypes/phi-brain.css` — 저널 입력창, 유일한 강조 버튼 "정리하기", 과목 태그, Future
  Item 행. 새 색상 토큰은 추가하지 않고 `theme.css`의 기존 토큰만 사용). 과목은 hover-reveal 리스트, Future Item은
  아코디언, 프로필은 드로어로 구성 — 모두 키트에 이미 있는 패턴을 그대로 재사용했다.
- 이 초안은 정적 프로토타입이며 데이터는 예시(사용자가 실제로 작성했던 BI/AOR/SI 저널 발췌)다. 실제 앱 구현은 아니다.

## Phi Brain 확정 사항 (2026-09-12, 사용자 지시 · Claude Code 반영)

위 스타일 키트 위에 사용자가 직접 지시해 확정한 것. 수치는 `design/prototypes/phi-brain.css` §1 토큰이 유일한 출처다.

- **최소화 원칙(사용자 지시):** 색·토큰·스타일 값은 앞으로도 최소 개수로 유지한다. 새 값을 추가하기 전에 기존 토큰으로 해결한다.
- **색상:** 흰 바탕 + 4색(`--ink` 주 텍스트, `--gray` 보조 텍스트 전부, `--line` 테두리, `--fill` 면). 키트의 17개
  색 이름은 호환용으로 이 4색에 매핑만 해 두고 새 규칙에서는 쓰지 않는다. 채워진 버튼은 "정리하기" 하나.
- **폰트 크기:** 페이지 전체 10pt 단일.
- **레이아웃:** 헤더 좌상단 로고(이미지) + 두 줄 워드마크(이미지) → 검색 → 우상단 프로필. 좌측 고정 사이드바 + 남은
  공간 중앙의 본문. 로고·사이드바 Tab1 라벨·푸터가 같은 좌측선(`--text-start`)에 정렬.
- **사이드바:** Tab1(Journaling · General · Course) / Tab2(하위 항목, 12개 과목은 알파벳순). 호버 시 라벨에 맞춘
  padding 박스(`--fill`, 20px squircle) + 10px 우측 이동 + 좌측 화살표(→) — 키트의 reveal-list 인터랙션을 따름.
- **푸터:** 배경 없음, 전체 `--gray`, 링크는 GitHub 하나.
- **모양:** 모든 부드러운 컨트롤(네비 탭, pill, 목록 행, 정리하기 버튼)은 `--radius` 하나(20px, squircle)를 쓴다.
  예외는 인라인 코드 하나(`--radius-sm` 4px) — 태그가 아니라 코드로 읽혀야 해서.

### Journaling 본문 (2026-09-12, 사용자가 GPT와 정리한 기획을 바탕으로 Claude Code가 구성)

"기록을 시작하고, 이어 쓰고, 정리까지 마치는 공간". 파일: `design/prototypes/home.html` + `journal.js`.

1. **맥락:** "오늘의 저널" + 날짜(오늘 기본, 지난 날짜 선택 가능, 미래 불가) · 제목(선택, 비우면 "M월 D일 저널") ·
   다룬 과목(선택, 접힘. AI 분류 힌트로만 사용, 작성 후에도 지정 가능. 칩을 누르는 즉시 저장되고, 바깥 클릭·Esc로도 닫힘 — "완료"는 필수 확인이 아님). 날짜 선택은 브라우저 기본 달력이 아니라
   페이지 스타일의 자체 달력(흰 카드 + `--shadow-float`, 원형 날짜, 선택일만 `--ink`, 블러 해제로 등장, 방향키 이동).
2. **하나의 문서:** 기본은 4F 박스 없는 빈 문서, 안내 문구 "오늘의 저널링을 적어주세요"(지난 날짜는 "M월 D일의 저널링을
   적어주세요"). 4F는 입력칸 4개가 아니라 문서 안의 소제목이고, "4F 템플릿"을 눌렀을 때만 생긴다. 소제목은 `--fill` pill 박스로 본문과 구분한다.
   4F pill에 호버하면 오른쪽에 도움 질문이 회색으로, 블러가 풀리며 나타난다(별도 "작성 도움" 버튼 없음).
   "4F 템플릿"은 토글 — 누르면 4F 박스 네 개가 생기고, 다시 누르면 박스(와 빈 줄)만 사라지고 쓴 내용은 남는다.
   박스가 있는 동안 버튼은 눌림 상태. 붙여넣기는 서식 없이.
   - 삽입 줄: 4F 템플릿 | 과목 · 체크리스트. **과목**은 본문에 과목 박스(테두리 pill — 4F의 채운 pill과 구분)를 넣고,
     박스를 누르면 12개 과목 메뉴가 뜬다. 고른 과목은 "다룬 과목" 힌트에도 자동 추가.
   - 서식 줄(드래그한 글자에 적용): B · I · U · S | 인용(왼쪽 선) · 코드(Pretendard 그대로, 옅은 배경+테두리+`--radius-sm`).
     현재 선택의 서식이 눌림 상태로 표시. (Unifont는 시도 후 사용자 결정으로 제외 — 페이지 전체가 Pretendard 한 가지.)
   - **Future Item에 등록하기:** Future Item 박스 줄 오른쪽 끝의 조용한 pill. 그 섹션의 줄마다 과목을 정해 Future Item 탭으로
     보낸다 — 위쪽 과목 박스 → 줄 앞 과목 코드("BI — …") → 다룬 과목이 하나뿐이면 그 과목 → 과목 미지정 순(AI 연결 전 임시 규칙).
     다시 등록하면 아직 등록되지 않은 원문 줄만 추가한다. Future Items에서 수정·이동한 기존 항목을 덮어쓰지 않는다.
3. **저장 ≠ 확정:** 날짜별 초안 자동 저장("초안 저장됨 · 시각"). 초안은 과목 아카이브에 들어가지 않는다. "정리하기"만이
   AI 분석 → 검토 → 확정으로 이어지고, 정리 중·실패·다시 시도가 같은 자리에 표시된다.
4. **이어 쓰기:** 편집기 아래 접힘 행 3개 — 이어서 작성하기, 검토가 필요한 저널, 지난 할 일 돌아보기(다른 날짜에 등록한 미완료 Future Item).

- 인터랙션 원칙: 이동하는 항목은 네비와 같은 화살표+이동+fill, 펼치는 항목은 ▾ 회전 + 키트 아코디언(slide+blur).

### Future Items 페이지 (2026-09-12, 사용자 요구사항 · Claude Code 구현)

파일: `design/prototypes/future.js`(저장·화면·드래그·메뉴·토스트, Journaling↔Future Item 전환). 새 토큰 없음.
주소: `#future-item`, 필터별 `#future-item/general` · `/temp` · `/BI` 등(새로고침·뒤로가기 유지).

- **필터**(한 번에 하나): All / General / 임시 | 과목 약어 12개(다룬 과목과 같은 순서). pill, 선택 = 채움 + 굵게, 미완료 개수 표시.
  전체 과목명은 `title`·`aria-label`로 제공. All을 뺀 필터는 드래그 도착지.
- **작성줄**(필터 바로 아래): [실행할 행동] [소속 ▾] [추가]. 소속 기본값은 필터를 따름(과목→그 과목, General→General,
  All·임시→미지정), 사용자가 바꿀 수 있음. Enter 추가(한글 조합 중 Enter는 무시), 빈 내용 무시, 추가 후 입력칸 비우고 포커스 유지.
  현재 필터에 안 보이는 곳에 추가하면 토스트로 위치 안내("… 박스에 추가했어요 · 보기"). 추가 버튼이 이 화면의 유일한 채운 버튼.
- **박스**: 가는 테두리(`--line`)만, 그림자 없음. 제목(약어_과목명 또는 General) · 미완료 개수 · 즐겨찾기(☆/★, 항상 보임) ·
  미완료 목록 · 접힌 "완료한 항목 N". 임시는 점선 테두리의 별도 영역(즐겨찾기 없음).
- **All 배치**: 임시(있을 때) → "즐겨찾기"(고정한 순서 그대로, 비어도 유지) → "그 외"(최근 추가 순, 항목이 있는 박스만).
  박스 안은 최근 추가(현재 소속에 들어온 시각) 순. 이동해 온 항목은 새 항목 취급, 문구 수정·완료 체크는 순서 불변.
  특정 과목·General·임시 필터에서는 비어 있어도 박스와 안내를 보여줌.
- **항목**: 원형 체크박스 + 행동 문장 + ⋯ 메뉴(수정 · 소속 변경 · 원문 저널 열기(있을 때) · 삭제). ⋯는 항상 보임(호버 전용 아님).
- **소속 변경**: 드래그(도착 가능한 곳 점선 외곽선, 올려둔 곳 실선+채움, 끄는 항목은 흐리게) 또는 ⋯ → 소속 변경(키보드·모바일 경로).
  같은 소속이면 무변화, ID·완료 상태 유지, 이동 후 토스트 "… 박스로 옮겼어요 · 되돌리기". 현재 필터에서 사라지면 목적지를 알리고
  키보드 포커스를 되돌리기로 옮김.
- **토스트**: 화면 아래 가운데 흰 카드(`--shadow-float`). 되돌리기(이동·삭제), 보기(다른 곳에 추가), 다시 시도(저장 실패). 스크린리더용 live 영역 별도.
- **저장 실패**: 변경 전 상태로 되돌리고 오류 토스트 + 다시 시도. 추가 실패 시 입력한 문장은 남김.
- **저널 연동**: 저널의 "Future Item에 등록하기"는 아직 등록 안 된 줄만 추가(원문 문장 기준) — Future Item에서 한 수정·이동은
  다시 등록해도 덮어쓰지 않음. 이어 쓰기의 "지난 할 일"은 미완료 항목(현재 저널이 등록한 것 제외).
- **폰트 로드:** Pretendard v1.3.9를 jsDelivr CDN의 dynamic subset CSS로 불러온다(`home.html` `<head>`). 설치 여부와
  무관하게 모든 사용자에게 표시되고, 페이지에 쓰인 글자 범위의 조각만 내려받는다. 사용 굵기는 400·700 두 가지.

## 아직 정하지 않은 것

- 과목 상세·검토 화면·Assignment Manage 본문은 미구현. Future Items 실행 목록은 구현됐으며 추가 사용성 점검 대상이다.
- 한글·영문 메뉴 표기 최종안(홈 화면 초안은 한글로 작성함: 저널·과목·실행 → "과목" 섹션, "미해결 Future Item" 등).
- 모바일: Claude가 Future Items 375px 레이아웃을 검증했다고 기록했다. 터치 드래그는 미지원이며 메뉴로 소속 변경. 실제 기기 점검은 남아 있다.
- 원문 비교 방식(Codex 제안의 데스크톱 2열 비교 모드는 이 키트로 아직 구현 안 함).
- 다크 모드는 키트 자체가 라이트 전용이라 다크 모드를 만들려면 새 토큰 세트가 필요함 — 필요 여부 자체가 미정.
- 서버·계정·AI·Gmail 연동의 구현 및 배포 범위.
