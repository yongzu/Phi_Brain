## 최신 UI 수정 (2026-09-12, 사용자 요청 · Codex)

- 과목 정식 약어는 EWA. 기존 EAI는 호환 별칭으로만 처리하며 기존 항목·즐겨찾기·저널 과목 선택을 EWA로 읽는다.
- Journaling 다룬 과목에 General 추가. General 하나를 선택한 저널의 Future Item은 General로 등록한다.
- 다룬 과목 선택칸의 음수 왼쪽 여백을 제거해 AL 선택 배경이 잘리지 않도록 수정.
- Future Item에 등록하기는 정리하기 왼쪽의 기본 미체크 옵션이다. 체크 후 정리하기를 누르면 Future Item 등록을 수행한다. 등록 성공 후 체크 해제; 실패 시 유지하고 재시도 가능. AI 정리는 여전히 미연결이다.
- 저널 체크리스트 원은 9px, Future Items 완료 원은 10px로 축소.
- 이후 본문의 예전 EWA→EAI 및 등록 버튼 위치 설명보다 이 절을 우선한다.

현재 기준: `92d1808`의 Journaling·Future Items 프런트엔드 프로토타입. 아래 초기 제안보다 이후 확정 스타일과 화면별 구현 절을 우선한다. Assignment Manage 본문은 미구현이다.

## Phi Brain 확정 사항 (2026-09-12, 사용자 지시 · Claude Code 반영)

위 스타일 키트 위에 사용자가 직접 지시해 확정한 것. 수치는 `design/prototypes/phi-brain.css` §1 토큰이 유일한 출처다.

- **최소화 원칙(사용자 지시):** 색·토큰·스타일 값은 앞으로도 최소 개수로 유지한다. 새 값을 추가하기 전에 기존 토큰으로 해결한다.
- **색상:** 흰 바탕 + 4색(`--ink` 주 텍스트, `--gray` 보조 텍스트 전부, `--line` 테두리, `--fill` 면). 키트의 17개

- **폰트 크기:** 페이지 전체 10pt 단일.
- **레이아웃:** 헤더 좌상단 로고(이미지) + 두 줄 워드마크(이미지) → 검색 → 우상단 프로필. 좌측 고정 사이드바 + 남은
  공간 중앙의 본문. 로고·사이드바 Tab1 라벨·푸터가 같은 좌측선(`--text-start`)에 정렬.
- **사이드바:** Tab1(Journaling · General · Course) / Tab2(하위 항목, 12개 과목은 알파벳순). 호버 시 라벨에 맞춘
  padding 박스(`--fill`, 20px squircle) + 10px 우측 이동 + 좌측 화살표(→) — 키트의 reveal-list 인터랙션을 따름.
- **푸터:** 배경 없음, 전체 `--gray`, 링크는 GitHub 하나.
- **모양:** 모든 부드러운 컨트롤(네비 탭, pill, 목록 행, 정리하기 버튼)은 `--radius` 하나(20px, squircle)를 쓴다.
  예외는 인라인 코드 하나(`--radius-sm` 4px) — 태그가 아니라 코드로 읽혀야 해서.

### Journaling 본문 (2026-09-12, 사용자가 GPT와 정리한 기획을 바탕으로 Claude Code가 구성)

"기록을 시작하고, 이어 쓰고, 정리까지 마치는 공간". 파일: `design/prototypes/home.html` + `journal.js`.

1. **맥락:** "오늘의 저널" 제목 · 저널 제목 입력(선택, 비우면 "M월 D일 저널") · 다룬 과목(선택, AI 분류 힌트로만 사용,
   작성 후에도 지정 가능) · 그 아래 날짜(오늘 기본, 지난 날짜 선택 가능, 미래 불가). 다룬 과목은 **2026-09-13부터 접힘
   아코디언이 아니라 Future Item 작성 카드의 소속 칩과 같은 방식으로 항상 펼쳐져 있다** — 칩을 누르면 즉시 토글·저장되고
   따로 열고 닫을 상태가 없다(다중 선택은 그대로 유지). 날짜 선택은 브라우저 기본 달력이 아니라 페이지 스타일의 자체
   달력(흰 카드 + `--shadow-float`, 원형 날짜, 선택일만 `--ink`, 블러 해제로 등장, 방향키 이동) — 이 컴포넌트를
   Future Item의 마감 날짜 선택창도 별도 인스턴스로 재사용한다.
2. **하나의 문서:** 기본은 4F 박스 없는 빈 문서, 안내 문구 "오늘의 저널링을 적어주세요"(지난 날짜는 "M월 D일의 저널링을
   적어주세요"). 4F는 입력칸 4개가 아니라 문서 안의 소제목이고, "4F 템플릿"을 눌렀을 때만 생긴다. 소제목은 `--fill` pill 박스로 본문과 구분한다.
   4F pill에 호버하면 오른쪽에 도움 질문이 회색으로, 블러가 풀리며 나타난다(별도 "작성 도움" 버튼 없음).
   "4F 템플릿"은 토글 — 누르면 4F 박스 네 개가 생기고, 다시 누르면 박스(와 빈 줄)만 사라지고 쓴 내용은 남는다.
   박스가 있는 동안 버튼은 눌림 상태. 붙여넣기는 서식 없이.
   - 삽입 줄: 4F 템플릿 | 과목 · 체크리스트. **과목**은 본문에 과목 박스(테두리 pill — 4F의 채운 pill과 구분)를 넣고,
     박스를 누르면 12개 과목 메뉴가 뜬다. 고른 과목은 "다룬 과목" 힌트에도 자동 추가.
   - 서식 줄(드래그한 글자에 적용): B · I · U · S | 인용(왼쪽 선) · 코드(Pretendard 그대로, 옅은 배경+테두리+`--radius-sm`).
     현재 선택의 서식이 눌림 상태로 표시. (Unifont는 시도 후 사용자 결정으로 제외 — 페이지 전체가 Pretendard 한 가지.)
   - **Future Item에 등록하기:** Future Item 박스 줄 오른쪽 끝의 조용한 pill. 그 섹션의 줄마다 과목을 정해 Future Item 탭으로
     보낸다 — 위쪽 과목 박스 → 줄 앞 과목 코드("BI — …") → 다룬 과목이 하나뿐이면 그 과목 → 과목 미지정 순(AI 연결 전 임시 규칙).
     다시 등록하면 아직 등록되지 않은 원문 줄만 추가한다. Future Items에서 수정·이동한 기존 항목을 덮어쓰지 않는다.
3. **저장 ≠ 확정:** 날짜별 초안 자동 저장("초안 저장됨 · 시각"). 초안은 과목 아카이브에 들어가지 않는다. "정리하기"만이
   AI 분석 → 검토 → 확정으로 이어지고, 정리 중·실패·다시 시도가 같은 자리에 표시된다.
4. **이어 쓰기:** 편집기 아래 접힘 행 3개 — 이어서 작성하기, 검토가 필요한 저널, 지난 할 일 돌아보기(다른 날짜에 등록한 미완료 Future Item).

- 인터랙션 원칙: 이동하는 항목은 네비와 같은 화살표+이동+fill, 펼치는 항목은 ▾ 회전 + 키트 아코디언(slide+blur).

  4열 박스 그리드가 여유 있게 배치되도록 했다.
- **작성 카드(2026-09-13 재설계, 순서는 같은 날 다시 조정):** 한 줄 바가 아니라 세로로 쌓인 카드. 위에서부터
  ① 소속 칩 한 줄(Journaling "다룬 과목"과 같은 `course-chips`/`pill` 스타일이지만 항목당 소속은 하나라 단일 선택),
  ② **마감 켜기/끄기 체크박스** + (체크했을 때만 보이는) 마감 날짜·시간, ③ 2줄 높이 `<textarea>`(Enter로 추가, 한글
  조합 중 Enter는 무시), ④ 추가 버튼. 마감 날짜는 Journaling 날짜 선택창과 동일한 `.datepicker`/`.dp-*` 컴포넌트를
  별도 인스턴스로 재사용(미래 날짜도 선택 가능), 마감 시간은 같은 카드 스타일의 커스텀 3열 스크롤 선택(오전/오후·시·분,
  브라우저 기본 `time`/`datetime-local` 위젯 아님 — 그 위젯이 좁은 박스 안에서 레이아웃을 깨서 교체함). 체크박스가
  꺼져 있으면 어떤 날짜가 표시돼 있든 마감 없음으로 저장되고, 켜면 그 순간 보이는 날짜(기본 오늘)+시간이 그대로 마감이
  된다 — 날짜를 따로 안 바꿔도 체크박스 자체가 "마감 있음"의 신호다. 추가 후에는 체크박스도 다시 꺼지고 필드도 숨겨진다.
- **박스**: 가는 테두리(`--line`)만, 그림자 없음. 제목(약어_과목명 · 커스텀 박스 이름 · General) · 미완료 개수 · "⋯" 메뉴
  (즐겨찾기 토글은 모든 과목/커스텀 박스, 이름 바꾸기·삭제는 커스텀 박스에서만 — 실제 과목은 고정 커리큘럼이라 제외) ·
  미완료 목록 · 접힌 "완료한 항목 N". 삭제 시 그 안의 항목은 임시로 이동, 삭제도 되돌리기 토스트를 지원.
- **General/임시:** 상단 한 줄에 반반씩 고정 배치(둘 다 즐겨찾기·드래그 대상 아님) — General이 왼쪽, 임시가 오른쪽.
- **과목/커스텀 박스 그리드**: 4열(좁은 화면은 2열→1열), 즐겨찾기 지정 시 "즐겨찾기"/"과목" 두 그룹으로 나뉘지만 순서
  자체는 각 그룹 안에서 사용자가 정한 `boxOrder`를 따른다. **드래그로 자유롭게 재배치**(상하좌우 모두) — 드롭 대상과의
  배열 인덱스 비교로 방향을 정하므로 커서 위치가 아니라 어디에 놓았는지로 항상 동작한다. 상단의 "정렬 ▾" 버튼을 누르면
  옆에 뜨는 메뉴(최신 추가순/마감 급한순/알파벳순)로 한 번에 재배열할 수 있고, 이후에도 드래그로 계속 다듬을 수 있다.
  즐겨찾기는 순서에 영향을 주지 않는, 순수 그룹 표시 기능이다. 그리드 끝의 점선 "+ 박스 추가" 타일로 새 커스텀 박스를 만든다.
- **항목**: 원형 체크박스 + 행동 문장 + 마감 배지(있을 때, 지났으면 굵게) + ⋯ 메뉴(수정 · 마감 설정/변경 · 소속 변경 ·
  원문 저널 열기(있을 때) · 삭제). ⋯는 항상 보임(호버 전용 아님).
- **소속 변경**: 드래그(도착 가능한 곳 점선 외곽선, 올려둔 곳 실선+채움, 끄는 항목은 흐리게) 또는 ⋯ → 소속 변경(키보드·모바일 경로).
  같은 소속이면 무변화, ID·완료 상태 유지, 이동 후 토스트 "… 박스로 옮겼어요 · 되돌리기". 현재 필터에서 사라지면 목적지를 알리고
  키보드 포커스를 되돌리기로 옮김. (항목 드래그와 박스 재배치 드래그는 서로 다른 상태로 관리되어 섞이지 않는다.)
- **토스트**: 화면 아래 가운데 흰 카드(`--shadow-float`). 되돌리기(이동·삭제), 보기(다른 곳에 추가), 다시 시도(저장 실패). 스크린리더용 live 영역 별도.
- **저장 실패**: 변경 전 상태로 되돌리고 오류 토스트 + 다시 시도. 추가 실패 시 입력한 문장은 남김.
- **저널 연동**: 저널의 "Future Item에 등록하기"는 아직 등록 안 된 줄만 추가(원문 문장 기준) — Future Item에서 한 수정·이동은
  다시 등록해도 덮어쓰지 않음. 이어 쓰기의 "지난 할 일"은 미완료 항목(현재 저널이 등록한 것 제외).
- **폰트 로드:** Pretendard v1.3.9를 jsDelivr CDN의 dynamic subset CSS로 불러온다(`home.html` `<head>`). 설치 여부와
  무관하게 모든 사용자에게 표시되고, 페이지에 쓰인 글자 범위의 조각만 내려받는다. 사용 굵기는 400·700 두 가지.
- **좌측 내비게이션(2026-09-13):** 모바일 폭(≤860px)에서 General/Course 그룹이 아코디언으로 접힌다(좌상단, 기존
  `StyleKit.createAccordion` 슬라이드+블러 애니메이션 재사용). 데스크톱에서는 항상 펼쳐진 채 클릭이 무시된다.

### Assignment Manage 페이지 (2026-09-12, 사용자 요구사항 · Claude Code 구현)

파일: `design/prototypes/assignment.js` + `home.html`의 `#view-assignment`. 백엔드: `server/`(Node, 외부 의존성 없음).
과제·셀프피드백을 관리하는 화면이라 Journaling·Future Items와 다르게 **표(table)** 형식이다 — 행은 12개 과목,
열은 과목명 / Assignment / Self-Feedback. 카드나 접힘 목록으로 만들지 않는다. 토큰(`--ink`·`--gray`·`--line`·`--fill`·
`--radius`)과 Pretendard, 사이드바·호버 스타일은 그대로 재사용하고 새 색상은 추가하지 않았다.

- **상단 툴바:** 이전 주 ‹ / 현재 주차와 기간(예: `Week 01 (09.07~09.13)`) / 다음 ›, Gmail 연결 상태 + 연결하기·연결 해제,
  마지막 동기화 시각(오류 있으면 같이 표시), 제출 상태 새로고침 버튼.
- **본문 표:** 헤더는 `Course(Figma)` / Assignment / Self-Feedback. 과목명은 클릭해도 이동하지 않고 호버 시 박스만 표시되며,
  옆의 별도 ↗ 아이콘이 수업 보드(Figma)로 이동한다. Assignment·Self-Feedback 각 칸도 상태 배지(원 + 라벨) + 제출폼
  바로가기(↗, 별도 링크라 상태를 바꾸지 않음)로 동일한 형태. 상태 배지를 누르면 우측 하단에 상세 패널이 블러 해제로
  나타난다(Future Item 토스트와 같은 `popIn`/`popOut` 재사용). 본문 섹션은 Journaling/Future Item과 별도로 폭을 넓혔다
  (`.shell:has(.view-assignment:not([hidden])){max-width:920px}`).
- **상세 패널:** 과목·주차·과제/셀프피드백, 확인 방식, 확인메일 수신 시각, 확인메일 열기(Gmail 스레드 링크), 추출된 제출물
  링크(있는 필드만), 직접 확인으로 표시 / 해당 없음으로 표시 / 수동 확인 취소 버튼. '해당 없음'을 눌렀는데 이미 확인메일이
  있으면 저장하지 않고 토스트로 충돌을 알리고 "표시하기"를 눌러야 강제 적용된다(자동으로 어느 한쪽을 택하지 않음).
- **상태 5종:** 미확인(빈 원) / 제출 확인(메일, 채운 원) / 직접 확인(채운 원) / 해당 없음(점선 원) / 확인 필요(충돌 — 채운
  원 + 바깥 링, 수동 "해당 없음"과 확인메일이 동시에 있는 경우).
- **백엔드 없음 상태:** API가 응답하지 않으면 표를 숨기고 "백엔드에 연결할 수 없어요 — `node server/index.js`를 실행해주세요"
  문구만 보여준다. 가짜 데이터를 보여주지 않는다.
- **라우팅:** `#assignment`. Future Item·Journaling과 같은 `show()`가 뷰를 바꾸는데, 그 함수가 뷰가 아닌 동안 해시를 지우기
  때문에(`history.replaceState`) `assignment.js`는 해시를 직접 읽지 않고 `future.js`가 쏘는 `phibrain:view` 커스텀 이벤트와
  `PhiBrain.getCurrentView()`로 자신이 보여지는 시점을 안다.

## 아직 정하지 않은 것

- 과목 상세·검토 화면 본문은 미구현. Assignment Manage와 Future Items 실행 목록은 구현됐으며 추가 사용성 점검 대상이다.
- 한글·영문 메뉴 표기 최종안(홈 화면 초안은 한글로 작성함: 저널·과목·실행 → "과목" 섹션, "미해결 Future Item" 등).
- 모바일: Claude가 Future Items 375px 레이아웃을 검증했다고 기록했다. 터치 드래그는 미지원이며 메뉴로 소속 변경. 실제 기기 점검은 남아 있다.
- 원문 비교 방식(Codex 제안의 데스크톱 2열 비교 모드는 이 키트로 아직 구현 안 함).
- 다크 모드는 키트 자체가 라이트 전용이라 다크 모드를 만들려면 새 토큰 세트가 필요함 — 필요 여부 자체가 미정.
- 서버·계정·AI·Gmail 연동의 구현 및 배포 범위.
