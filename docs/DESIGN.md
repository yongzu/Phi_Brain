## 최신 UI 수정 (2026-09-12, 사용자 요청 · Codex)

- 과목 정식 약어는 EWA. 기존 EAI는 호환 별칭으로만 처리하며 기존 항목·즐겨찾기·저널 과목 선택을 EWA로 읽는다.
- Journaling 다룬 과목에 General 추가. General 하나를 선택한 저널의 Future Item은 General로 등록한다.
- 다룬 과목 선택칸의 음수 왼쪽 여백을 제거해 AL 선택 배경이 잘리지 않도록 수정.
- Future Item에 등록하기는 정리하기 왼쪽의 기본 미체크 옵션이다. 체크 후 정리하기를 누르면 Future Item 등록을 수행한다. 등록 성공 후 체크 해제; 실패 시 유지하고 재시도 가능. AI 정리는 여전히 미연결이다.
- 저널 체크리스트 원은 9px, Future Items 완료 원은 10px로 축소.
- 이후 본문의 예전 EWA→EAI 및 등록 버튼 위치 설명보다 이 절을 우선한다.

  드로어·검색 드롭다운의 인터랙션 타이밍까지 코드로 확정됨(각각 180–520ms, `cubic-bezier` 이징 지정, `prefers-reduced-motion` 대응 포함).
- Claude Code가 이 키트를 적용해 홈 화면 초안을 만들었다: `design/prototypes/home.html`

## Phi Brain 확정 사항 (2026-09-12, 사용자 지시 · Claude Code 반영)

위 스타일 키트 위에 사용자가 직접 지시해 확정한 것. 수치는 `design/prototypes/phi-brain.css` §1 토큰이 유일한 출처다.

- **최소화 원칙(사용자 지시):** 색·토큰·스타일 값은 앞으로도 최소 개수로 유지한다. 새 값을 추가하기 전에 기존 토큰으로 해결한다.

  공간 중앙의 본문. 로고·사이드바 Tab1 라벨·푸터가 같은 좌측선(`--text-start`)에 정렬.
- **사이드바:** Tab1(Journaling · General · Course) / Tab2(하위 항목, 12개 과목은 알파벳순). 호버 시 라벨에 맞춘
  padding 박스(`--fill`, 20px squircle) + 10px 우측 이동 + 좌측 화살표(→) — 키트의 reveal-list 인터랙션을 따름.
- **푸터:** 배경 없음, 전체 `--gray`, 링크는 GitHub 하나.
- **모양:** 모든 부드러운 컨트롤(네비 탭, pill, 목록 행, 정리하기 버튼)은 `--radius` 하나(20px, squircle)를 쓴다.
  예외는 인라인 코드 하나(`--radius-sm` 4px) — 태그가 아니라 코드로 읽혀야 해서.

### Journaling 본문 (2026-09-12, 사용자가 GPT와 정리한 기획을 바탕으로 Claude Code가 구성)

"기록을 시작하고, 이어 쓰고, 정리까지 마치는 공간". 파일: `design/prototypes/home.html` + `journal.js`.

1. **맥락:** "오늘의 저널" 제목(다른 화면과 공유하는 `.journal-heading`보다 2pt 크고 `#000` 순정 검정 — `#journal-heading`
   ID 선택자로 이 화면에만 적용) · 저널 제목 입력("9월 12일 저널" placeholder, 선택, 비우면 "M월 D일 저널" —
   2026-09-13부터 입력값·placeholder 모두 `#000`, 왼쪽 padding을 `--tab-pad-x`만큼 줘서 텍스트 시작점이 아래
   다룬 과목의 첫 칩 텍스트와 정확히 맞도록 함) · 다룬 과목 칩(선택, AI 분류 힌트로만
   사용, 작성 후에도 지정 가능 — **2026-09-13부터 "다룬 과목" 라벨 텍스트 없이 칩만** 있다) · 그 아래 날짜(오늘 기본,
   지난 날짜 선택 가능, 미래 불가). 다룬 과목은 접힘 아코디언이 아니라 Future Item 작성 카드의 소속 칩과 같은 방식으로
   항상 펼쳐져 있다 — 칩을 누르면 즉시 토글·저장되고 따로 열고 닫을 상태가 없다(다중 선택은 그대로 유지, 라벨이 없어도
   `aria-label="다룬 과목"`로 스크린리더에는 여전히 이름이 전달된다). 날짜 선택은 브라우저 기본 달력이 아니라 페이지
   스타일의 자체 달력(흰 카드 + `--shadow-float`, 원형 날짜, 선택일만 `--ink`, 블러 해제로 등장, 방향키 이동) — 이
   컴포넌트를 Future Item의 마감 날짜 선택창도 별도 인스턴스로 재사용한다.
2. **하나의 문서:** 기본은 4F 박스 없는 빈 문서, 안내 문구 "오늘의 저널링을 적어주세요"(지난 날짜는 "M월 D일의 저널링을
   적어주세요"). 4F는 입력칸 4개가 아니라 문서 안의 소제목이고, "4F 템플릿"을 눌렀을 때만 생긴다. 소제목은 `--fill` pill 박스로 본문과 구분한다.
   4F pill에 호버하면 오른쪽에 도움 질문이 회색으로, 블러가 풀리며 나타난다(별도 "작성 도움" 버튼 없음).
   "4F 템플릿"은 토글 — 누르면 4F 박스 네 개가 생기고, 다시 누르면 박스(와 빈 줄)만 사라지고 쓴 내용은 남는다.
   박스가 있는 동안 버튼은 눌림 상태. 붙여넣기는 서식 없이. **서식 줄(B·I·U·S·인용·코드)은 2026-09-13부터 텍스트를
   실제로 드래그 선택했을 때만 나타난다** — 시작 화면엔 아무 도구줄도 안 뜬 빈 편집기만 보인다(`selectionchange`마다
   `refreshFormatState()`가 선택 상태를 보고 `hidden`을 토글).
   - 삽입 줄: 4F 템플릿 | 과목 · 체크리스트. **과목**은 본문에 과목 박스(테두리 pill — 4F의 채운 pill과 구분)를 넣고,
     박스를 누르면 12개 과목 메뉴가 뜬다. 고른 과목은 "다룬 과목" 힌트에도 자동 추가.
   - 서식 줄(드래그한 글자에 적용): B · I · U · S | 인용(왼쪽 선) · 코드(Pretendard 그대로, 옅은 배경+테두리+`--radius-sm`).
     현재 선택의 서식이 눌림 상태로 표시. (Unifont는 시도 후 사용자 결정으로 제외 — 페이지 전체가 Pretendard 한 가지.)
   - **Future Item에 등록하기:** Future Item 박스 줄 오른쪽 끝의 조용한 pill. 그 섹션의 줄마다 과목을 정해 Future Item 탭으로
     보낸다 — 위쪽 과목 박스 → 줄 앞 과목 코드("BI — …") → 다룬 과목이 하나뿐이면 그 과목 → 과목 미지정 순(AI 연결 전 임시 규칙).
     다시 등록하면 아직 등록되지 않은 원문 줄만 추가한다. Future Items에서 수정·이동한 기존 항목을 덮어쓰지 않는다.
3. **저장 ≠ 확정:** 날짜별 초안 자동 저장("초안 저장됨 · 시각"). 초안은 과목 아카이브에 들어가지 않는다. "정리하기"만이
   AI 분석 → 검토 → 확정으로 이어지고, 정리 중·실패·다시 시도가 같은 자리에 표시된다.
4. **이어 쓰기:** 편집기 아래 접힘 행 3개 — 이어서 작성하기, 검토가 필요한 저널, 지난 할 일 돌아보기(다른 날짜에 등록한 미완료 Future Item).

`--radius`)과 Pretendard, 사이드바·호버 스타일은 그대로 재사용하고 새 색상은 추가하지 않았다.

- **상단 툴바:** 이전 주 ‹ / 현재 주차와 기간(예: `Week 01 (09.07~09.13)`) / 다음 ›, Gmail 연결 상태 + 연결하기·연결 해제,
  마지막 동기화 시각(오류 있으면 같이 표시), 제출 상태 새로고침 버튼.
- **본문 표:** 헤더는 `Course(Figma)` / Assignment / Self-Feedback. 과목명은 클릭해도 이동하지 않고 호버 시 박스만 표시되며,
  옆의 별도 ↗ 아이콘이 수업 보드(Figma)로 이동한다. Assignment·Self-Feedback 각 칸도 상태 배지(원 + 라벨) + 제출폼
  바로가기(↗, 별도 링크라 상태를 바꾸지 않음)로 동일한 형태. 상태 배지를 누르면 우측 하단에 상세 패널이 블러 해제로
  나타난다(Future Item 토스트와 같은 `popIn`/`popOut` 재사용). 본문 섹션은 Journaling/Future Item과 별도로 폭을 넓혔다
  (`.shell:has(.view-assignment:not([hidden])){max-width:920px}`).
- **상세 패널:** 과목·주차·과제/셀프피드백, 확인 방식, 확인메일 수신 시각, 확인메일 열기(Gmail 스레드 링크), 추출된 제출물
  링크(있는 필드만), 직접 확인으로 표시 / 해당 없음으로 표시 / 수동 확인 취소 버튼. '해당 없음'을 눌렀는데 이미 확인메일이
  있으면 저장하지 않고 토스트로 충돌을 알리고 "표시하기"를 눌러야 강제 적용된다(자동으로 어느 한쪽을 택하지 않음).
- **상태 5종:** 미확인(빈 원) / 제출 확인(메일, 채운 원) / 직접 확인(채운 원) / 해당 없음(점선 원) / 확인 필요(충돌 — 채운
  원 + 바깥 링, 수동 "해당 없음"과 확인메일이 동시에 있는 경우).
- **백엔드 없음 상태:** API가 응답하지 않으면 표를 숨기고 "백엔드에 연결할 수 없어요 — `node server/index.js`를 실행해주세요"
  문구만 보여준다. 가짜 데이터를 보여주지 않는다.
- **라우팅:** `#assignment`. Future Item·Journaling과 같은 `show()`가 뷰를 바꾸는데, 그 함수가 뷰가 아닌 동안 해시를 지우기
  때문에(`history.replaceState`) `assignment.js`는 해시를 직접 읽지 않고 `future.js`가 쏘는 `phibrain:view` 커스텀 이벤트와
  `PhiBrain.getCurrentView()`로 자신이 보여지는 시점을 안다.

### Journal Archive 페이지 (2026-09-13, 사용자 요구사항 · Claude Code 구현)

지금까지 쓴 저널을 과목 기준으로 돌아보는 화면. 새 저장소 없이 `journal.js`의 기존 `store`(localStorage)를 읽기만 한다.
파일: `home.html`의 `#view-archive` + `journal.js`(같은 IIFE 안에 추가, 별도 파일 없음). 새 색상·토큰 없음.

- **진입:** 사이드바 General > Journal Archive에 `data-view="journal-archive"`를 달아 `future.js`의 `views` 레지스트리에
  등록했다(이전까지는 링크만 있고 화면이 없는 죽은 버튼이었다). 주소는 `#journal-archive`, 필터별 `#journal-archive/AL`·
  `/general` 등 — Future Item의 필터 주소 패턴과 동일. 다만 필터 상태를 `future.js`가 아니라 `journal.js` 쪽 archive
  모듈이 직접 관리한다(`show()`는 이 뷰로 넘어갈 때 해시를 지우지 않도록만 예외 처리하고, 실제 읽기·쓰기는
  `phibrain:view` 이벤트를 받은 journal.js가 한다 — Assignment Manage와 같은 방식).
- **상단 필터:** Future Item의 `.fi-filters`/`.fi-filter` pill을 그대로 재사용, 한 번에 하나 선택. 순서는 `All, General,
  AL, AOR, BI, EWA, IAE, IPS, PC, RW, SI, TF, VT, WI` — General은 Future Item처럼 "전체 보기" 자리를 내주고 그 자체가
  하나의 필터 값이 됐다(All이 전체 보기를 맡는다). 각 필터 옆에 그 과목이 들어간 저널 개수를 `.f-count`로 표시.
- **목록:** 필터 아래 `resume-list`(이어서 작성하기와 같은 시각 스타일, 아코디언 밖에서 쓰므로 들여쓰기만 제거)로 최신
  날짜순 목록. 각 행은 제목(비어 있으면 "M월 D일 저널") · 다룬 과목(있는 만큼, `General`/과목 코드) · 마지막 저장 시각.
  클릭하면 기존 `window.PhiBrain.openJournal(date)`(Future Item의 "원문 저널 열기"가 이미 쓰던 함수)로 Journaling 탭의
  그 날짜를 그대로 연다 — Archive 전용 열람 로직을 새로 만들지 않았다.
- **다대다 과목 필터:** 저널 하나가 여러 과목에 동시에 태그될 수 있는 기존 규칙을 그대로 따른다(Future Item·Assignment
  Manage의 "소속 하나" 규칙과 다름) — 필터는 배열 `includes()`로 "포함"만 검사하므로 저널 하나가 여러 필터에 동시에
  나타날 수 있고, 이는 의도된 동작이다.
- **정직한 데이터:** 홈 화면 "이어서 작성하기"가 섞어 쓰는 가짜 예시(`EXAMPLES`)·검토 목업(`REVIEW`)은 Archive에 전혀

- **범위 제외:** 정리(AI) 결과·검토 상태 표시, 검색·페이지네이션·월별 그룹핑·삭제, 기기 간 동기화 —
  전부 이번 구현에 포함하지 않았다(안내 문구로 "이 브라우저에만 저장" 고지).

  재사용, 새 아코디언 구현 없음). 펼친 상태는 필터를 바꿔도 접히지 않고 그대로 유지된다("고정") — 재렌더링 직전에

  않고 그대로 동작한다(요소를 ID로 한 번만 찾아 캐싱해두는 방식이라 부모가 바뀌어도 참조는 그대로 유효). 위에 뜨는
