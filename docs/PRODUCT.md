## 확정된 목표와 범위

Phi Design Institute의 학습 저널을 과목별로 정리·축적하는 AI Learning Second Brain 웹앱을 만든다.
사용자는 12개 과목을 배우며 통합 4F 저널을 디스코드에 날짜순으로 기록하고 있다.
날짜 중심의 기록에서 과목별 학습 흐름과 인사이트를 다시 찾기 어려운 문제가 있다.

Phase 1은 Journal Organizer MVP다.

1. 기존 4F 저널을 입력한다.
2. 내용을 의미 단위(semantic chunk)로 나눈다.
3. 각 내용을 12개 과목 중 하나 이상으로 분류한다.
4. Fact / Feeling / Finding / Future Item으로 구조화한다.
5. 과목별 memory에 저장한다.

요구사항·스타일 논의를 거쳐 Journaling·Future Items 프런트엔드 프로토타입 구현이 진행됐다. 백엔드까지 완성된 앱은 아니다.
GitHub 저장소는 `https://github.com/yongzu/Phi_Brain`이다.

## 이후 단계의 비전

- Phase 2: 과목별 저널·인사이트·작업물·피드백을 흡수하는 Course Agent.
- Phase 3: 과목 간 공통 패턴과 사고방식·역량 변화를 찾는 Second Brain / Agent Village.
- Phase 1 설계안은 하나의 AI 처리 흐름과 과목별 context를 전제로 한다. 독립적인 AI 12개를 운영하는 구조는 요구하지 않는다.

## MVP 기능 제안

- 개인용을 우선한다. 다중 사용자·인증 방식은 미정이다.
- 날짜와 제목을 지정하고 저널 원문을 한 번에 붙여넣는다. 4개 입력칸으로 강제하지 않는다.
- AI 결과를 원문과 비교하며 내용·과목·4F를 수정하고 확정한다.
- 과목별 기록을 날짜·4F·검색어로 찾는다.
- Future Item의 미완료·완료를 관리한다. 기한은 선택 사항이다.
- 디스코드 자동 수집, 파일 업로드, Agent 대화, 성장 분석은 후속 단계로 제안한다.

## 데이터 모델 제안

관계형 데이터 모델 초안이며, 특정 DB나 프레임워크는 선택하지 않았다.

| 엔터티 | 목적 | 주요 필드 |
|---|---|---|
| Course | 과목과 분류 기준 | id, name, aliases, description, keywords |
| Journal | 날짜별 통합 저널 | id, owner_id, date, title, current_revision_id |
| JournalRevision | 원문 수정 이력 | id, journal_id, raw_text, version, created_at |
| AnalysisRun | 분석 대상·실행 이력 | id, revision_id, status, model_version, prompt_version |
| Chunk | 원문의 의미 단위 | id, analysis_id, quote, source_start, source_end, order |
| MemoryItem | 정리된 4F 항목 | id, text, four_f_type, review_status |
| MemoryEvidence | 정리 항목의 원문 근거 | memory_id, chunk_id |
| MemoryCourse | 여러 과목과의 연결 | memory_id, course_id, classification_reason |
| ActionItem | Future Item 실행 상태 | memory_id, status, due_at, completed_at |

원문 버전 → 분석 → Chunk ↔ MemoryItem → 여러 Course의 관계다.

### 모델 운영 원칙 제안

- 원문을 보존하고 모든 정리 항목에서 근거를 찾을 수 있게 한다.
- 과목별 memory는 연결된 정리 항목의 집합이다. 과목마다 내용을 복제하지 않는다.
- 정리 항목 하나에는 4F 유형 하나를 부여한다. 복합 내용은 나누고 원문 근거를 공유할 수 있다.
- 없는 감정·통찰·행동을 만들어 채우지 않는다.
- 과목을 판단하기 어려우면 미분류로 남기고 사용자가 정한다.
- 재분석은 새 초안으로 생성한다. 기존 확정 기록을 즉시 덮어쓰지 않는다.
- 재확정 시 중복 기록을 방지한다. 완료 상태·사용자 수정의 보존 및 항목 대응 정책은 구현 전에 구체화한다.
- 원문 위치의 단위, 삭제 정책, 사용자별 접근 제어, 트랜잭션 및 재시도 방식은 구현 설계 때 정한다.

## Future Item (사용자 확정, 2026-09-12)

사용자가 요구사항을 직접 작성해 구현 시작을 지시했다(Claude Code가 `design/prototypes/`에 구현).

- Future Item은 **구체적으로 실행할 행동(Activity)**이며 투두리스트처럼 관리한다. 흐름: 빠르게 작성 → 과목별 분류 → 실행 → 완료.
- **Assignment Manage(과제·셀프피드백 제출 관리)와 별개.** Future Item을 완료해도 과제 제출 상태는 바뀌지 않는다.
- **소속은 항목당 하나:** 특정 과목 / 사용자가 추가한 커스텀 박스 / General / 임시(미지정). General은 "특정 과목이 아님"으로
  분류 완료된 상태, 임시는 아직 분류하지 않은 상태 — 둘을 합치지 않으며 가짜 과목으로 취급하지 않는다.
- 이 원칙은 Future Item에만 적용한다. 저널·인사이트의 복수 과목 연결 정책은 바꾸지 않는다.
- 과목 약어·순서는 기존 과목 목록 하나를 기준으로 통일(EWA 같은 다른 표기는 별도 과목으로 만들지 않음).
- **커스텀 박스(2026-09-13 추가):** 12개 고정 과목 외에 사용자가 이름을 지어 박스를 추가할 수 있다("+ 박스 추가"). 실제 과목과
  달리 이름 변경·삭제가 가능하며, 삭제 시 그 안의 항목은 임시로 이동한다(과목 자체는 삭제·이름변경 불가 — 고정 커리큘럼).
- **마감일(2026-09-13 추가):** 항목에 선택적으로 마감 날짜/시간을 붙일 수 있다("이번 범위 제외"에서 해제됨). 반복 일정, 하위
  할 일, 알림, AI 분류는 여전히 이번 범위 밖.
- **박스 순서(2026-09-13 추가):** General/임시를 제외한 과목·커스텀 박스는 사용자가 드래그로 순서를 바꿀 수 있고,
  최신 추가순/마감 급한순/알파벳순 일괄 정렬도 제공한다. 즐겨찾기는 순서에 영향 없이 그룹만 나눈다.
- **활동(항목) 순서도 드래그로(2026-09-13 확정):** 박스뿐 아니라 그 안의 활동도 드래그로 순서를 바꿀 수 있다.
- **삭제만 ✕, 수정은 더블클릭, 마감은 수정 중에만 뜨는 +(2026-09-13 재확정 — 같은 날 있었던 "펜·시계·✕ 3개 상시
  노출" 단계를 사용자가 다시 되돌림):** 행동 문장 우측엔 삭제(✕)만 항상 보인다. 수정은 문장을 더블클릭하면 바로
  그 자리에서 시작되고(펜 아이콘 없음), 마감이 없는 행동은 그 수정 상태에 들어갔을 때만 우측에 + 버튼이 떠서
  그걸로 새로 붙인다(시계 아이콘 없음) — 이미 마감이 붙은 행동은 수정 상태와 무관하게 마감 배지 자체를
  더블클릭해서 바꾼다. 기존 항목 ⋯ 메뉴(수정·마감·소속 변경·원문 저널 열기·삭제)는 여전히 없다 — 소속 변경은
  드래그로만 하고, "원문 저널 열기"는 대체 없이 없앴다(사용자 결정, 변경 없음).
  행동 문장은 한 줄로 말줄임(...) 처리해 두 번째 줄로 넘어가 아이콘과 겹치지 않는다. 지난 마감 배지는 색만
  진해지고 굵게 표시되지 않는다(이전엔 굵게 표시했음). 행동 문장·마감 배지·수정 입력칸 모두 8pt.
- **마감 선택은 작성 카드와 같은 UI(2026-09-13 확정 — 처음엔 브라우저 기본 날짜/시간 선택창이 떴었다):** 시계
  아이콘을 누르면 Future Item 작성 카드에서 마감을 정할 때와 똑같은 달력·시간 선택 카드가 뜬다. 브라우저 기본
  `datetime-local` 위젯은 쓰지 않는다.
- **즐겨찾기 별표(2026-09-13 확정, 같은 날 텍스트 `★`→사용자 제공 SVG로 교체):** 과목/커스텀 박스마다 우측
  상단에 항상 별이 있고, 기본은 옅은 회색, 즐겨찾기하면 `#333333` 채움 별로 바뀐다. Journal Archive의 과목별
  카드도 같은 별표로 즐겨찾기한다.
- **주차(WK) 탐색기(2026-09-13 확정, AskUserQuestion으로 설계 확인 후 구현):** 과목/커스텀 박스 그리드는 그대로 두고,
  그 위에 Assignment Manage와 같은 모양의 `‹ Week NN (MM.DD~MM.DD) ›` 탐색기를 **새 축**으로 추가 — 그리드 자체가
  주차별로 재편되는 게 아니라, 탐색기로 고른 주에 만든 항목만 지금의 박스 그리드에 보이는 방식. 항목의 주차는
  **만든 날짜(`createdAt`)** 기준이고, **완료된 항목도** 주차 필터에 포함된다(박스별 "완료한 항목" 아코디언과는
  별개 축으로 동시 적용). 지난 주차를 보는 동안에도 체크·수정·삭제·드래그는 막지 않는다(읽기 전용 여부는
  확정한 적 없음 — 필요해지면 별도 결정). 완료 취소는 이 작업과 무관하게 2026-09-12 최초 구현부터 이미 있던
  기능이었다(체크박스를 다시 누르면 되돌아감).
- **못 한 행동은 이번 주로 이월(2026-09-14 사용자 확정 — 위 "만든 날짜 기준"을 대체):** 지난주에 만들고 완료하지
  못한 행동은 이번 주 화면으로 넘어오고, **지난주 화면에서는 사라진다**(두 주에 동시에 보이지 않는다). 규칙:
  완료한 항목은 **완료한 주**(`doneAt`, 없으면 `createdAt`)에 남고, 미완료 항목은 만든 주가 지났으면 늘 이번 주.
  저장값을 옮겨 쓰지 않고 볼 때마다 계산한다(`itemWeek`) — 마이그레이션이 없고, 지난주에서 넘어와 이번 주에
  완료하면 이번 주 기록으로 남으며, 지난 주 화면에서 완료를 취소하면 그 항목은 이번 주로 옮겨 간다.
  "이월됨" 표시는 따로 없다(요청 없음).
- **박스 필터 복수 선택(2026-09-14 사용자 확정):** 과목/General/임시/커스텀 필터 pill을 여러 개 켤 수 있다.
  All을 누르면 선택 해제, 켜진 pill을 다시 누르면 꺼지고 마지막 하나를 끄면 All로 돌아간다. 고른 박스들은 화면의
  박스 순서대로 **한 줄 최대 4개**로 보인다(하나만 골라도 1/4 칸 고정, 넓게 늘리지 않음 — 2026-09-14 사용자 지시). 새 행동의 기본 소속은 박스를
  딱 하나 골랐을 때만 그 박스, 여러 개면 미지정. URL은 `#future-item/BI,AL`. 박스 정렬 메뉴는 All에서만.

### 데이터 모델 제안과의 충돌 (미결정 — 사용자 결정 필요)

- 위 "데이터 모델 제안"은 `ActionItem`이 `memory_id`로 `MemoryItem`에 붙고, `MemoryItem`은 `MemoryCourse`로 **여러 과목**에
  연결된다. 이대로면 Future Item이 여러 과목에 속하게 되어 "소속 하나" 확정과 충돌한다.
- 현재 실제로 저장된 데이터에는 충돌이 없다: 프로토타입의 기존 Future Item(v1)은 항목당 과목이 0~1개였고, v2로 자동 전환했다
  (과목 없음 → 임시). 삭제·복제한 연결 없음. v1 저장 키는 백업으로 그대로 둠.
- 전환 제안(에이전트 제안, 미확정): `ActionItem`에 자체 소속 필드(`scope`: course | general | unassigned, `course_id`)를 두어
  `MemoryCourse`와 분리한다. 저널·인사이트 쪽 복수 과목 연결은 유지한다. 여러 과목에 걸친 정리 항목에서 Future Item을 만들 때는
  첫 과목을 자동 선택하거나 과목별로 복제하지 않고, 임시로 넣거나 사용자가 그 자리에서 하나를 고르게 한다.

## Assignment Manage (사용자 확정, 2026-09-12 — 구현 시작 지시)

사용자가 상세 요구사항을 직접 작성해 구현 시작을 지시했다(Claude Code가 `server/`, `design/prototypes/assignment.js`에 구현).
참고 자료: 사용자가 준 와이어프레임·과목 URL 표(`Assignmetn Manage.pdf`) — 형식과 URL 값만 참고하고 스타일은 따르지 않았다.

- 주차별 12개 과목의 과제·셀프피드백 제출 확인과 수업 보드·제출폼 바로가기.
- 셀프피드백을 저널에 가져오지 않는다. Future Item 완료 여부와 제출 상태를 연결하지 않는다(서로 독립).
- 상태 4종 + 1(구현 중 추가): 미확인 / 제출 확인(메일) / 직접 확인 / 해당 없음 / **충돌**(수동 "해당 없음"과 확인메일이 동시에 있는 경우 — 자동으로 어느 한쪽을 택하지 않고 사용자에게 확인을 요청).
- 완료 개수 = 제출 확인 + 직접 확인, 분모에서 해당 없음 제외.
- Gmail 연동은 규칙 기반(AI 미사용): 발신자(`forms-receipts-noreply@google.com`) + **제목의 `[과목] 과제|셀프피드백 제출`만으로
  과목·구분 판단**(M1, 2026-09-14 사용자 확정 "제목만 보고 판단"). 실제 확인메일 27통으로 전 과목·과제/셀프피드백 형식이 같음을
  확인해, 예전의 "EWA 과제만 자동 확인, 나머지는 검토 대기열" 제한은 없앴다. 셀프피드백은 과목마다 메일이 따로 와서 본문으로 여러
  과목을 찾는 보조 검사는 두지 않는다. 과제·셀프피드백 제출이 아닌 폼(`[Phi] …` 등)은 무시.

- **M3 주 1회 자동 동기화(2026-09-14 사용자 확정 · 같은 날 구현):** 파일 `design/prototypes/data/assignment-status.json`,
  실행 `server/export-snapshot.js`(`--full` = 전체 다시 계산), 워크플로 `.github/workflows/assignment-sync.yml`.

    주차(늦게 낸 과제도 원래 주차에). "제출 안 함"은 쓰지 않는다(미확인은 파생). 메일 ID·링크·수신 시각 등은 공개 파일에 넣지 않는다.
  - **보완:** 인식 규칙(M1)을 고친 뒤 과거 메일을 다시 판정하는 "전체 다시 계산" 수동 옵션(`"manual"` 칸은 보존).
  - **사전 조건(사용자):** OAuth 동의 화면을 프로덕션으로 전환(테스트 상태면 refresh token 7일 만료), 전환 뒤 Gmail 재연결,

## Journal Archive (사용자 확정, 2026-09-13 — 구현 시작 지시)

사용자가 상세 요구사항을 직접 작성해 구현 시작을 지시했다(Claude Code가 `design/prototypes/home.html`·`journal.js`에 구현).

- 지금까지 실제로 저장한 저널을 과목 기준으로 돌아보는 화면이다. 새로 쓰는 화면이 아니고, 새 저장소도 만들지 않는다 —
  Journaling이 이미 쓰는 localStorage 초안을 그대로 읽기만 한다.
- 상단 필터는 Journaling·Future Item과 같은 과목 목록이되, 맨 앞이 "General"이 아니라 "All"이다. All은 전체 보기,
  그 뒤로는 General과 과목 12개가 필터 값으로 온다.
- 저널 하나는 여러 과목에 동시에 속할 수 있다(기존 저널·인사이트 원칙 그대로, Future Item의 "소속 하나" 규칙과는 다름) —
  과목 필터는 "그 과목이 다룬 과목에 포함되면" 보여주는 포함 검사이며, 저널 하나가 여러 필터에 동시에 나타나는 것은
  버그가 아니라 의도된 동작이다.
- 홈 화면 "이어서 작성하기"가 쓰는 가짜 예시 데이터(EXAMPLES)·검토 목업(REVIEW)은 Archive에 절대 포함하지 않는다 —
  실제로 저장된 것만 다룬다는 원칙을 지킨다.
- 이번 범위 제외: 정리(AI) 결과·검토 상태 표시, 검색·페이지네이션·월별 그룹핑, 기기 간 동기화.
- **삭제하기(2026-09-13 확정, 사용자 요구사항 — "수정하기 말고 삭제하기버튼도 구현"):** 행/카드 `⋯` 메뉴에 "수정하기" 옆에
  "삭제하기"를 추가했다. **2026-09-14 사용자 지시로 확인 단계 추가:** "삭제하기"를 누르면 같은 `⋯` 팝업이
  `"제목" 저널을 삭제할까요? / 삭제 / 취소`로 바뀌고(브라우저 기본 confirm 대화상자 아님, 기본 포커스는 "취소"),
  "삭제"를 눌러야 지운다. 지운 뒤의 "되돌리기" 토스트는 그대로 유지한다. 지우는
  날짜를 그 순간 Journal Archive 안에서 편집 중이었다면 편집을 닫고 목록으로 돌아가고, Journaling 탭에서 보고 있던
  날짜였다면 그 화면도 빈 문서로 되돌아간다(둘 다 방금 지운 초안이 살아있는 것처럼 보이지 않도록). 그 날짜의 즐겨찾기
  카드(`date::course` 키)도 같이 정리한다.
- **행 클릭 = 그 자리에서 미리보기(2026-09-13 확정):** All 필터의 목록 행을 누르면 Journaling으로 이동하지 않고
  저장된 본문이 그 자리에서 펼쳐진다. 펼친 상태는 필터를 바꿔도 유지된다("고정").
- **수정은 Journal Archive 안에서(2026-09-13 확정 — Journaling 탭으로 이동하던 것에서 변경):** 행/카드의 `⋯` 메뉴
  → "수정하기"를 고르면 Journaling 작성 화면이 Journal Archive 탭 안에 그대로 나타나 그 자리에서 고칠 수 있다.
  Journaling 탭으로 완전히 옮겨가는 것이 아니다.
- **과목 필터 = 카드 그리드(2026-09-13 확정):** All이 아니라 특정 과목을 고르면 저널 전체가 아니라 그 과목에
  해당하는 내용만 카드로 보여준다(Future Item의 박스 형태를 재사용, 2열). 카드 단위(날짜×과목)로 "즐겨찾기"를 할
  수 있고, 즐겨찾기한 카드가 그 과목 안에서 맨 앞에 온다.
- **과목 필터 복수 선택(2026-09-14 사용자 확정):** Future Item·Findings와 같은 켜고 끄기(All = 해제, 마지막 하나를 끄면
  All). 여러 과목을 고르면 고른 과목이 들어간 (날짜, 과목)마다 카드가 한 장씩 — 두 과목을 다룬 날은 과목별로 두 장 —
  같은 2열 그리드에 나오고, 이때만 카드 메타에 과목 코드를 붙여 구분한다(`BI · 오후 3:12`). 정렬은 즐겨찾기 먼저 →
  최신 날짜 → 같은 날은 과목 순서. URL `#journal-archive/BI,EWA`. 필터 기준(그날의 "다룬 과목" 포함 여부)은 그대로.
- **All 탭에 학기 주차·요일 표시(2026-09-13 확정):** All 탭의 각 행에 그 저널이 학기 몇 주차인지(`WK1`, `WK2`…)와
  날짜 뒤 요일을 표시한다(예: `WK1 9월 13일(일)`). 주차 기준은 Assignment Manage와 같은 학기 1주차 시작일이다.

## Findings (사용자 확정, 2026-09-14 — 구현 시작 지시)

사이드바의 죽어 있던 "Insight Archive" 링크를 2026-09-13에 "Findings"로 개명한 데 이어, 실제 화면을 만들었다.
Journal Archive와 같은 원칙 — **읽기 전용, 새 저장소 없음** — 으로, 저널 본문에 이미 쓴 내용에서 뽑아 보여준다.

- **무엇을 보여주나:** 저장된 각 저널의 **Finding**(4F 중 하나) 섹션 — 그 소제목과 다음 소제목 사이의 내용 —
  을 인사이트로 취급한다. Fact·Feeling·Future Item 섹션은 대상이 아니다.
- **과목 배정 기준 = 본문 과목 태그(2026-09-14 사용자 지시로 변경):** Finding 섹션 안의 과목 박스를 기준으로
  자른다 — 과목 박스 뒤부터 다음 과목 박스 전까지가 그 과목의 몫이고, 그 박스에만 들어간다(Journal Archive의
  `courseChunks`와 같은 규칙). 태그가 하나라도 있으면 그날의 "다룬 과목" 칩은 보지 않는다.
  - **왜 바꿨나:** 처음엔 "칩만 체크해도 놓치지 않게" 그날의 `courses[]` 칩을 기준으로 삼았는데, 칩을 여러 개
    고른 날이면 BI 태그를 단 Finding 하나가 General·AOR·BI 박스에 똑같이 복제돼 나타났다. 사용자가 이를
    버그로 지적("과목태그를 기준으로 BI에만 적용한다") — 어느 과목 얘기인지는 글쓴이가 본문 태그로 이미
    명시했으니 그쪽이 칩보다 정확한 신호다.
  - **폴백 없음 — 과목 태그를 단 것만 보여준다(2026-09-14 사용자 확정, 같은 날 두 번째 수정):** 처음엔 태그 없는
    Finding을 칩→General로, 첫 태그 앞 앞머리를 General로 떨어뜨렸는데, BI 태그 위의 빈 줄(`<p><br></p>`)까지
    "General 1"(내용 없는 날짜만 있는 항목)로 잡혔다. 사용자 지시 "findings는 과목선택을 한 것만 보여주면 돼" —
    태그가 없는 Finding, 첫 태그 앞 내용은 Findings에 나타나지 않는다(저널 원문에는 그대로 남아 있음).
    General도 본문 태그로 General을 고른 경우에만 잡힌다. 각 조각 앞뒤의 빈 줄은 잘라낸다.
  - **빈 과목은 표시하지 않는다:** 내용이 없는 과목은 필터 pill도 박스도 그리지 않는다(All + 내용 있는 과목만).
    하나도 없으면 안내 문구 한 줄. 비어 있는 과목으로 딥링크(`#findings/AOR`)하면 All로 돌아간다.
  - 박스 안에서는 과목 태그 자체를 다시 그리지 않는다 — 어느 박스에 들어있는지가 이미 과목을 말해 준다
    (Journal Archive 카드와 동일).
- **레이아웃 = Future Item과 같은 박스 그리드, 폭도 동일(1500px):** "저널아카이브처럼 위에 All/General+과목별
  필터, 아래에 박스"라는 사용자 요구사항대로 필터 줄은 Journal Archive와 같은 컴포넌트(`.fi-filters`)를, 박스
  그리드는 Future Item과 같은 컴포넌트(`.fi-list`/`.fi-box`)를 그대로 재사용했다. 단 **한 줄에 2개**(Future
  Item은 4개) — Finding은 한 줄짜리 할 일이 아니라 문단이라 열 폭이 약 두 배 필요하다(2026-09-14 사용자 지시).
  All은 내용이 있는 과목 박스만 보여준다. **과목 필터는 복수 선택(2026-09-14 사용자 확정)** — Future Item과 같은
  켜고 끄기 방식(All = 해제, 마지막 하나를 끄면 All), 고른 과목들이 화면 순서대로 **한 줄 최대 2개**, URL은
  `#findings/BI,EWA`(내용 없는 과목은 딥링크로 들어와도 빠진다).
- **각 박스 안:** 그 과목에 걸린 Finding들을 최신순으로, 원문 서식(굵게·기울임·인용 등 — `.editor` 스타일 재사용)
  그대로 보여주고 바로 아래 작은 글씨로 날짜만 붙인다. 즐겨찾기·드래그 재배치·수정·삭제는 없음(읽기 전용이라
  범위 밖) — 고치려면 Journaling/Journal Archive에서 원문을 고쳐야 한다.
- **수정하기(2026-09-22 사용자 지시):** 박스 머리줄의 "수정하기"를 누르면 그 박스 안에서 그 과목의 Finding 조각만 고친다. 툴바는 저널링과 같은 서식 버튼(굵게·기울임·밑줄·취소선·하이라이트·인용·코드). 4F 템플릿과 과목 박스는 조각을 쪼개므로 없다. 붙여넣기도 줄과 **굵게**만 살린다. 저장하기(또는 Ctrl+Enter)는 원래 저널의 그 자리(`날짜::과목::n`)를 바꾸고, 취소는 버린다. 한 번에 박스 하나만.
- **넘버링 = 박스 하나(2026-09-22 사용자 지시):** 과목 태그 아래에서 `1. …`/`1) …`로 시작하는 줄마다 새 박스. 번호 없는 다음 줄은 그 번호에 붙고, 첫 번호 앞 내용은 따로 한 박스, 번호가 하나도 없으면 예전처럼 태그 하나 = 박스 하나. Shift+Enter로 한 문단에 이어 쓴 번호 줄도 나눈다. `3.5점` 같은 소수는 번호가 아니다. 기존 저널도 번호만 달면 바로 나뉜다(데이터 변환 없음 — 보여줄 때마다 나눈다). 박스 키 `날짜::과목::n`의 n이 나뉜 박스 순번이 되므로, 예전 저널에 번호를 달면 그 저널의 별표가 다른 박스로 옮겨갈 수 있다.
- **숨기기(2026-09-22 사용자 지시 — 처음엔 "삭제하기"였다가 같은 날 바꿈):** 박스 머리줄의 "숨기기" → 박스가 없어지지 않고 맨 아래 "숨긴 박스 N" 영역으로 간다(위와 48px 띄움, 되돌리기 토스트). 거기서 "숨기기 해제"로 제자리. 원본 저널은 그대로. 숨긴 목록은 박스 글자의 지문으로 기억(`날짜::과목::해시`, 로그인 시 서버 `findings_hidden`, 아니면 이 브라우저) — 저널을 고쳐 순서가 바뀌어도 다른 박스가 숨지 않고, 그 박스 글자를 고치면 숨김이 풀린다. 필터 개수는 숨긴 박스도 센다.
- **배치 = 두 세로 줄 쌓기(2026-09-22):** 행 맞춤 격자 대신, 박스마다 그때 더 짧은 줄 아래에 붙인다 — 옆 박스가 길어도 아래에 빈 칸이 생기지 않는다. 박스 사이 16px. 560px 이하는 한 줄. → 같은 날 **한 줄에 박스 하나**로 바꿈(`FINDINGS_COLS = 1`), 본문 폭 1500 → 1300 → 1100 → 700px.
- **Findings 번호·순서(2026-09-22 사용자 지시):** 순서 = 별표한 박스(별표한 순서) → 나머지는 시간순(오래된 날짜부터, 같은 날은 저널에 쓴 순서). 박스 머리줄 앞에 그 순서대로 1, 2, 3… 번호(지금 보이는 필터 기준, 숨긴 박스는 번호 없음). 저널에 쓴 "1." 번호와는 별개 — 저널 번호는 박스를 나누는 표시로만 쓰고 박스에 보여줄 때는 뗀다(원문·수정 칸에는 그대로).
- **하이라이터(2026-09-22 사용자 지시 — Findings가 줄글이라 중요한 지점이 안 보여서):** 저널링 툴바와 Findings 수정 툴바에 색 칩 버튼(글자 없음) + ▾ 색 메뉴(노랑 · 파랑 · 빨강). 드래그한 글자를 `<mark>`로 칠한다(노랑 = 속성 없음, 파랑·빨강 = `data-hl`). 칩 버튼과 **Ctrl+H**는 마지막에 고른 색으로 칠하고, 이미 칠한 곳이면 걷어낸다. 메뉴에서 고르면 그 색을 기억하고(이 브라우저, `phibrain.highlightColor`), 이미 칠한 곳이면 그 색으로 바꾼다. 색은 4톤 팔레트의 예외 `--mark`·`--mark-blue`·`--mark-red`.
- **실행 취소(2026-09-22):** 두 에디터 모두 자체 기록으로 Ctrl/⌘+Z(되돌리기), Ctrl+Y · Ctrl/⌘+Shift+Z(다시 실행). 하이라이트·서식·타이핑(0.8초 안의 연속 입력은 한 칸)·붙여넣기 전부, 캐럿 위치까지 되돌린다. 데스크톱 앱 편집 메뉴의 실행 취소도 같은 기록을 쓴다. 날짜를 바꾸거나 Findings 수정을 새로 열면 기록도 새로 시작.
- **Future Item 작성칸 툴바(2026-09-22 사용자 지시):** 작성칸이 서식 에디터가 되고 위에 저널링과 같은 툴바(굵게·기울임·밑줄·취소선·하이라이트 3색·인용·코드), Ctrl+H·Ctrl+Z 동일. 항목에는 글자만 담은 `text`(토스트·접근성·저널 중복 확인용)와, 서식이 있을 때만 `html`을 저장(허용 태그만 남기고 정리). 항목을 더블클릭해 문구를 바꾸면 그 수정 칸은 글자 전용이라 서식은 빠진다(문구를 안 바꾸면 유지).
- **이번 범위 제외:** 검색, Finding이 아닌 다른 4F 유형 보기, 박스 순서 변경, 기기 간 동기화.

## 초기 화면 구조 제안 (현재 UI와 구분)

상시 메뉴: 저널 / 과목 / 실행.

| 화면 | 내용과 행동 |
|---|---|
| 저널 목록 | 날짜·제목·연결 과목·처리 상태, 새 저널 작성 |
| 저널 작성 | 날짜·제목·큰 원문 영역, 임시 저장, AI 정리 |
| 정리 결과 검토 | 4F 항목 수정, 복수 과목 선택, 제외, 근거 확인, 확정 저장 |
| 과목 목록·상세 | 12개 과목, 날짜별 누적 항목, 4F·기간·검색 필터 |
| 실행 목록 | 전체 Future Item, 과목 필터, 완료 처리, 원문 이동 |

검토 화면은 정리된 글 중심이며, 원문 비교를 켜면 데스크톱에서는 두 열로 보이는 안을 제안했다.
분석 실패 시 원문을 유지하고 재시도할 수 있어야 한다.

## 제안한 완료 기준

여러 과목이 섞인 저널을 입력하고, 결과를 수정·저장한 뒤 각 과목에서 원문 근거와 함께 다시 찾을 수 있다.
같은 항목이 여러 과목에 연결되어도 수정과 실행 상태가 일관되며, 재분석으로 중복되지 않는다.
